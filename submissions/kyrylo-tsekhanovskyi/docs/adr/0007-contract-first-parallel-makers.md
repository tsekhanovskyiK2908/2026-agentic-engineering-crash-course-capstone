# 0007. Contract-first, with backend and frontend makers in parallel

- Status: accepted · Date: 2026-09-27 · Decided by: human

## Context
The capstone wants parallel agents. Two makers editing one codebase collide unless their boundary is fixed.

## Decision
- The spec phase produces `openspec/changes/<change>/contracts/openapi.yaml`, which the human approves
  with the spec.
- `tasks.md` has `## Backend` and `## Frontend` sections. `be-maker` writes only `backend/`, and
  `fe-maker` writes only `frontend/`. Both treat `openspec/**` and AGENTS.md as read-only, and
  contract changes are escalated.
- Each side is held to the contract on its own: the backend with an integration test that compares
  `/openapi/v1.json` to the contract, and the frontend with types generated by `openapi-typescript`
  plus `HttpTestingController` tests.
- The sync point is the full `npm run check`, `npm run e2e`, `review:be` and `review:fe`.

## Consequences
- Real parallelism, without the frontend waiting for a running backend.
- Shared files (root `package.json`, `.gitignore`) are created in the skeleton phase and are read-only
  for the makers.
